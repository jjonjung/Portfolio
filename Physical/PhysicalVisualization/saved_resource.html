Part 1: AABB 바운딩 박스 시스템

Axis-Aligned Bounding Box Coordinate Transformation

AABB 바운딩 박스 계산

AABB Bounding Box Calculation

UBoxComponent (반투명 주황색)

핵심 수식

Min = Origin - Extent
Max = Origin + Extent

함수명

GetXYBounds()

설명

AABB (Axis-Aligned Bounding Box)는 객체를 감싸는 축 정렬 경계 상자입니다. Origin(중심점)과 Extent(반경)를 사용하여 Min과 Max 좌표를 계산합니다.

UV (0~1) → 월드 XY 좌표

UV to World XY Transformation

UV 공간에서 월드 공간으로의 선형 보간

핵심 수식

WorldXY = Lerp(Min, Max, ClampedUV)
X = Min.X + (Max.X - Min.X) × UV.X
Y = Min.Y + (Max.Y - Min.Y) × UV.Y

함수명

UVToWorldXY()

설명

정규화된 UV 좌표(0~1)를 실제 월드 공간의 XY 좌표로 변환합니다. FMath::Lerp를 사용하여 바운딩 박스의 Min과 Max 사이를 선형 보간합니다.

사용 예시

// UV (0.5, 0.5) → 월드 중심점
FVector2D worldPos =
  UVToWorldXY(0.5f, 0.5f);

월드 XY → UV (0~1)

World XY to UV Transformation

월드 공간에서 UV 공간으로의 범위 매핑

핵심 수식

UV = MapRangeClamped(Min, Max, 0, 1, WorldXY)
U = (WorldX - Min.X) / (Max.X - Min.X)
V = (WorldY - Min.Y) / (Max.Y - Min.Y)

함수명

WorldXYToUV()

설명

월드 공간의 XY 좌표를 정규화된 UV 좌표(0~1)로 역변환합니다. FMath::GetMappedRangeValueClamped를 사용하여 바운딩 박스 내에서의 상대적 위치를 계산합니다.

사용 예시

// 플레이어 위치 → 미니맵 UV
FVector2D uv =
  WorldXYToUV(PlayerLocation);

void UpdateSwingPhysics(float DeltaTime)
{
    // 1. 중력 적용
    Velocity.Z -= Gravity * DeltaTime;
    
    // 2. 위치 업데이트
    Position += Velocity * DeltaTime;
    
    // 3. 거리 계산
    FVector ToAnchor = Position - AnchorPoint;
    float Distance = ToAnchor.Size();
    
    // 4. 제약 조건 적용 (Distance > RopeLength)
    if (Distance > RopeLength)
    {
        FVector RopeDir = ToAnchor / Distance;
        
        // 4-1. 반지름 속도 제거
        float RadialVel = FVector::DotProduct(Velocity, RopeDir);
        if (RadialVel > 0)
        {
            Velocity -= RadialVel * RopeDir;
        }
        
        // 4-2. 위치 보정
        Position = AnchorPoint + RopeDir * RopeLength;
    }
    
    // 5. 감쇠 적용
    Velocity *= SwingDamping; // 0.995
}

문제 1: 단순 중력 적용

로프 제약이 없어 무한히 멀어지는 문제

❌ 문제 상황

  • •중력만 적용하면 캐릭터가 계속 아래로 가속
  • •앵커와의 거리 제한이 없어 무한히 멀어짐
  • •로프가 존재하지 않는 것처럼 동작
  • •빨간 점선 = 로프가 늘어남

✅ 해결 방법

// 거리 제약 적용
float Distance = (Position - Anchor).Size();

if (Distance > RopeLength)
{
    // 1. 로프 방향 계산
    FVector RopeDir = 
        (Position - Anchor) / Distance;
    
    // 2. 반지름 방향 속도 계산
    float RadialVel = 
        FVector::DotProduct(Velocity, RopeDir);
    
    // 3. 바깥으로 나가는 속도 제거
    if (RadialVel > 0)
    {
        Velocity -= RadialVel * RopeDir;
    }
    
    // 4. 위치 강제 보정
    Position = Anchor + RopeDir * RopeLength;
}

핵심 개념

거리 제약 (Distance Constraint)
캐릭터는 항상 앵커와 RopeLength 만큼의 거리를 유지해야 함
위치 보정 (Position Correction)
거리가 초과되면 강제로 로프 길이 위치로 이동
속도 제한 (Velocity Constraint)
로프 방향으로 바깥으로 나가는 속도 성분 제거

문제 2: 반지름 방향 속도 미제거

나선형으로 바깥으로 퍼지는 문제

❌ 문제 상황

  • •로프가 팽팽해져도 속도 벡터를 그대로 유지
  • •앵커 방향(반지름) 속도 성분이 계속 누적
  • •원운동이 아니라 나선형으로 바깥으로 퍼짐
  • •빨간 벡터 = 반지름 방향 속도 (제거 필요)

✅ 해결 방법: 벡터 분해

// 1. 로프 방향 정규화
FVector RopeDir = 
    (Position - Anchor).GetSafeNormal();

// 2. 속도를 반지름 + 접선으로 분해
float RadialVel = 
    FVector::DotProduct(Velocity, RopeDir);

FVector RadialComponent = 
    RadialVel * RopeDir;
    
FVector TangentComponent = 
    Velocity - RadialComponent;

// 3. 바깥으로 나가는 속도만 제거
if (RadialVel > 0) // 앵커에서 멀어지는 방향
{
    Velocity = TangentComponent; // 접선만 유지
}

벡터 분해 원리

반지름 성분 (Radial)
앵커 방향으로의 속도. 제거해야 원운동 유지
RadialVel = Dot(V, RopeDir)
접선 성분 (Tangent)
스윙 방향 속도. 유지해야 함
Tangent = V - Radial

왜 내적(Dot Product)?

내적은 한 벡터를 다른 벡터에 투영(projection)한 크기를 계산합니다.

A · B = |A| × |B| × cos(θ)
= A를 B 방향으로 투영한 길이 × |B|

문제 3: 위치 보정 미적용

프레임마다 오차 누적으로 로프가 늘어나는 문제

❌ 문제 상황

  • •속도만 수정하고 위치는 보정하지 않음
  • •프레임마다 미세한 수치 오차가 누적됨
  • •로프 길이가 시간이 지날수록 점점 늘어남
  • •이를 "Constraint Drift" 현상이라고 함

✅ 해결 방법: 위치 강제 보정

float Distance = (Position - Anchor).Size();

if (Distance > RopeLength)
{
    // 1. 방향 계산
    FVector Direction = 
        (Position - Anchor) / Distance;
    
    // 2. 반지름 속도 제거
    float RadialVel = 
        FVector::DotProduct(Velocity, Direction);
    if (RadialVel > 0)
    {
        Velocity -= RadialVel * Direction;
    }
    
    // 3. 위치 강제 보정 (핵심!)
    Position = Anchor + Direction * RopeLength;
    
    // 이렇게 하면 항상 정확히 RopeLength 유지
}

왜 위치 보정이 필요한가?

수치 오차 (Numerical Error)
부동소수점 연산은 완벽하지 않음. dt마다 미세한 오차 발생
오차 누적 (Error Accumulation)
60FPS라면 1초에 60번, 10초면 600번 오차 누적
제약 이완 (Constraint Relaxation)
결과적으로 "로프가 늘어나는" 비현실적 동작

위치 보정 vs 속도 보정

❌ 속도만 보정
이미 벗어난 위치는 그대로 → 오차 누적 → Drift
✅ 위치도 보정
매 프레임 정확한 위치로 강제 이동 → 오차 제거 → 안정적

실전 팁

  • • 위치 보정은 항상 속도 보정 "후"에 수행
  • • 보정 강도를 조절하여 부드러운 효과 가능
  • • 물리 엔진에서는 "Constraint Solver"가 이 역할

문제 4: 감쇠 미적용

에너지가 보존되어 무한히 스윙하는 문제

❌ 문제 상황

  • •마찰이나 공기 저항이 없는 이상적인 상태
  • •에너지가 보존되어 영원히 같은 속도로 스윙
  • •현실적이지 않은 물리 동작
  • •플레이어가 제어하기 어려움

✅ 해결 방법: 감쇠 적용

// 매 프레임 속도에 감쇠 적용
void UpdateSwing(float DeltaTime)
{
    // 1. 중력 적용
    Velocity.Z -= Gravity * DeltaTime;
    
    // 2. 위치 업데이트
    Position += Velocity * DeltaTime;
    
    // 3. 제약 조건 해결
    ApplyRopeConstraint();
    
    // 4. 감쇠 적용 (핵심!)
    Velocity *= SwingDamping; // 0.995
    
    // 매 프레임 0.5% 에너지 손실
    // → 자연스럽게 멈춤
}

감쇠의 물리적 의미

공기 저항 (Air Resistance)
속도가 빠를수록 저항도 커짐. 속도 제곱에 비례
로프 마찰 (Rope Friction)
로프가 앵커 포인트와 마찰하며 에너지 손실
관절 저항 (Joint Damping)
캐릭터의 몸이 공기를 가르며 에너지 소실

감쇠 계수 선택 가이드

0.99 ~ 0.995 (빠른 감쇠)
무거운 로프, 높은 공기 저항. 빠르게 멈춤
0.995 ~ 0.998 (보통 감쇠)
일반적인 스윙. 자연스러운 느낌 (권장)
0.998 ~ 0.999 (느린 감쇠)
가벼운 로프, 낮은 마찰. 오래 스윙함

게임 플레이 효과

  • • 감쇠가 있으면 플레이어가 타이밍 맞추기 쉬움
  • • 너무 강하면 답답함, 너무 약하면 제어 어려움
  • • 게임 플레이 테스트로 최적값 찾기
  • • 스킬/아이템으로 감쇠 조절 가능 (예: 가벼운 웹)

Spider-Man Swing Physics Problem

왼쪽: 구속 조건 없음 (나선형 이탈), 오른쪽: 로프 구속 적용 (원형 유지)

문제점

  • 1.단순히 중력만 적용하면 캐릭터가 앵커 포인트에서 무한히 멀어진다
  • 2.로프가 팽팽해진 순간 속도의 반지름 방향 성분을 제거하지 않으면 나선형으로 멀어짐
  • 3.위치 보정 없이 속도만 수정하면 프레임 간 누적 오차로 로프 길이가 늘어남

해결 방법

  • ✓속도 벡터를 반지름 방향 + 접선 방향으로 분해 (Dot Product 투영)
  • ✓로프가 팽팽할 때 반지름 방향 속도 성분 제거 → 접선 방향만 유지
  • ✓위치 보정: CorrectPosition = AnchorPoint - RopeDir × RopeLength
  • ✓매 프레임 SwingDamping 감쇠 적용으로 에너지 소실 표현

구현 조건

if
(Distance > RopeLength)
→ 반지름 방향 속도 제거
→ 위치 보정 적용

속도 벡터 분해

Velocity Vector Decomposition

v (원래 속도)
v_r (반지름)
v_t (접선)
r̂ (로프 방향)

핵심 수식

r̂ = (Anchor - Player) / Distance
v_r = (v · r̂) × r̂
반지름 방향 성분 (Radial)
v_t = v - v_r
접선 방향 성분 (Tangential)

Dot Product 투영

FVector RopeDirection = 
  (SwingAnchorPoint - PlayerLocation)
  .GetSafeNormal();

// v·r̂ = 내적 (스칼라)
float DotProduct = 
  FVector::DotProduct(
    SwingVelocity, 
    RopeDirection
  );

// v_r = (v·r̂) × r̂
FVector RadialVelocity = 
  DotProduct * RopeDirection;

물리적 의미

  • v_r:로프를 따라 움직이는 속도 (제거 대상)
  • v_t:로프에 수직인 속도 (유지하여 스윙 계속)
  • v = v_r + v_t:벡터 합성

Core Code Implementation

Skill1_SpiderManSwing.cpp

Unreal Engine C++
void USkill1_SpiderManSwing::CalculateSwingPhysics(
    ACharacterBase* Owner, 
    float DeltaTime
)
{
    FVector PlayerLocation = Owner->GetActorLocation();
    FVector ToAnchor       = SwingAnchorPoint - PlayerLocation;
    float   Distance       = ToAnchor.Size();
    FVector RopeDirection  = ToAnchor.GetSafeNormal();  // 플레이어 → 앵커 단위벡터

    // 중력 적용
    FVector CurrentVelocity = Owner->GetVelocity();
    FVector Gravity         = FVector(0, 0, -980.0f) * DeltaTime;
    SwingVelocity           = CurrentVelocity + Gravity;

    if (Distance > CurrentRopeLength)
    {
        // ── 속도 분해 ────────────────────────────────────
        // 반지름 방향 성분: v_r = (v · r̂) * r̂
        FVector RadialVelocity = 
            FVector::DotProduct(SwingVelocity, RopeDirection) 
            * RopeDirection;
        
        // 접선 방향 성분: v_t = v - v_r
        FVector TangentialVelocity = SwingVelocity - RadialVelocity;

        // 로프 팽팽할 때 반지름 성분 제거 (로프 바깥으로 나가지 않음)
        SwingVelocity = TangentialVelocity;

        // 위치 보정: 로프 길이 유지
        FVector CorrectPosition = 
            SwingAnchorPoint - RopeDirection * CurrentRopeLength;
        Owner->SetActorLocation(CorrectPosition);
    }

    // 감쇠 (공기저항 모사)
    SwingVelocity *= SwingDamping;

    if (UCharacterMovementComponent* Movement = Owner->GetCharacterMovement())
        Movement->Velocity = SwingVelocity;
}

1️⃣ 속도 분해

float dot = v · r̂
내적(Dot Product)으로 반지름 방향 성분 추출
v_r = dot × r̂
반지름 방향 속도 벡터
v_t = v - v_r
접선 방향 속도 벡터 (유지)

2️⃣ 위치 보정

CorrectPosition = Anchor - r̂ × L
L: 로프 길이 (CurrentRopeLength)
왜 필요한가?
속도만 수정하면 프레임 간 누적 오차로 플레이어가 서서히 멀어집니다. 매 프레임 정확한 위치로 보정해야 합니다.

3️⃣ 감쇠 적용

v_new = v × damping
일반적으로 0.99 ~ 0.995 사용
물리적 의미
공기 저항, 로프 마찰 등으로 인한 에너지 소실을 시뮬레이션합니다. 감쇠가 없으면 영구적으로 스윙합니다.

4️⃣ 조건 체크

if (Distance > RopeLength)

TMap O(1) 조회

Intent 기반 ActionRouter 아키텍처에서 빠른 검색 속도 보장

핵심 코드

// ActionRouter.h
TMap<EIntentType, TSubclassOf<UAction>> 
    ActionMap;

void InitializeActionMap()
{
    ActionMap.Add(
        EIntentType::Attack, 
        UFireAction::StaticClass()
    );
    ActionMap.Add(
        EIntentType::Retreat, 
        UMoveBackAction::StaticClass()
    );
    ActionMap.Add(
        EIntentType::Skill, 
        UUseSkillAction::StaticClass()
    );
}

// O(1) 검색
UAction* GetAction(EIntentType Intent)
{
    TSubclassOf<UAction>* Found = 
        ActionMap.Find(Intent);
    
    return Found ? 
        NewObject<UAction>(*Found) : 
        nullptr;
}

장점

  • ✓O(1) 시간 복잡도로 즉각적인 액션 조회
  • ✓if-else 체인 제거로 유지보수성 향상
  • ✓새로운 Intent 추가 시 Map에만 등록
  • ✓예측 가능한 성능 (프레임 드롭 없음)

vs 기존 방식

❌ if-else (O(n))
if (Intent == Attack) ...
else if (Intent == Retreat) ...
else if ...
✅ TMap (O(1))
ActionMap.Find(Intent)

사용 예시

// AI가 의도 결정 후 즉시 실행
EIntentType Intent = DecideIntent();
UAction* Action =
  ActionRouter->GetAction(Intent);
Action->Execute();

Sin/Cos 복합 함수 Movement

저비용 고효율 연산을 이용한 자비용 고효율 연산

핵심 코드

void AMoveAction::Execute()
{
    float Time = GetWorld()->GetTimeSeconds();
    
    // 랜덤하게 Sin 또는 Cos 선택
    bool bUseSin = FMath::RandBool();
    
    FVector CurrentLoc = Owner->GetActorLocation();
    FVector NewLocation = CurrentLoc;
    
    if (bUseSin)
    {
        // Sin 패턴: 좌우 웨이브
        NewLocation.Y += 
            FMath::Sin(Time * Speed) 
            * Amplitude;
    }
    else
    {
        // Cos 패턴: 상하 웨이브
        NewLocation.X += 
            FMath::Cos(Time * Speed) 
            * Amplitude;
    }
    
    Owner->SetActorLocation(NewLocation);
}

파라미터 제어

장점

  • ✓CPU 연산 비용이 매우 낮음 (하드웨어 최적화)
  • ✓부드럽고 자연스러운 움직임
  • ✓예측 가능한 패턴으로 디버깅 용이
  • ✓다수의 AI가 동시에 사용해도 성능 저하 없음

실전 활용

  • • 회피 패턴: 플레이어 공격을 피하면서 이동
  • • 순찰 경로: 일정 범위 내에서 웨이브 움직임
  • • 공중 유닛: 비행 패턴 시뮬레이션
  • • 랜덤성: FMath::RandBool()로 예측 불가능성 추가

Raycasting

200 유닛 범위 내 실시간 지형지물(장애물) 탐색

마우스를 움직여 AI의 시야 방향을 조정하세요

핵심 코드

bool AEnemyAI::RaycastObstacles()
{
    FVector StartLocation = GetActorLocation();
    
    // 8방향 레이캐스트
    for (int i = 0; i < 8; i++)
    {
        float Angle = (i / 8.0f) * TWO_PI;
        FVector Direction = FVector(
            FMath::Cos(Angle), 
            FMath::Sin(Angle), 
            0
        );
        
        FVector EndLocation = 
            StartLocation + Direction * 200.0f;
        
        FHitResult Hit;
        bool bHit = GetWorld()->LineTraceSingleByChannel(
            Hit, 
            StartLocation, 
            EndLocation,
            ECC_Visibility
        );
        
        if (bHit && Hit.GetActor())
        {
            // 장애물 발견!
            HandleObstacle(Hit);
        }
    }
}

활용 사례

  • 1.커버 찾기: 가장 가까운 cover 태그 오브젝트로 이동
  • 2.길찾기: 장애물 회피 경로 계산
  • 3.시야 체크: 플레이어와 사이에 벽이 있는지 확인

Component Pattern

기능 단위의 모듈화로 메모리 및 로직 관리 효율화

핵심 코드

// EnemyCharacter.h
class AEnemyCharacter : public ACharacter
{
    UPROPERTY()
    UMovementComponent* MovementComp;
    
    UPROPERTY()
    UAttackComponent* AttackComp;
    
    UPROPERTY()
    UPerceptionComponent* PerceptionComp;
    
    UPROPERTY()
    UHealthComponent* HealthComp;
};

// 사용 예시
void AEnemyCharacter::Tick(float DeltaTime)
{
    // 각 컴포넌트가 독립적으로 동작
    MovementComp->UpdateMovement(DeltaTime);
    AttackComp->ProcessAttack(DeltaTime);
    PerceptionComp->ScanEnvironment();
}

컴포넌트 구조

MovementComponent
• Sin/Cos 패턴 이동
• 장애물 회피
• 경로 추적
AttackComponent
• 조준 및 발사
• 스킬 사용
• 쿨다운 관리
PerceptionComponent
• Raycasting
• 플레이어 탐지
• 위협 평가
HealthComponent
• 체력 관리
• 데미지 처리
• 사망 이벤트

장점

  • ✓재사용성: 다른 캐릭터에도 동일한 컴포넌트 적용 가능
  • ✓모듈화: 각 기능이 독립적으로 동작, 디버깅 용이
  • ✓메모리 효율: 필요한 컴포넌트만 할당
  • ✓확장성: 새 기능 추가 시 새 컴포넌트만 생성
